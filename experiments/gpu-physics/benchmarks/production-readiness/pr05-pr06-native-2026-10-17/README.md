## Runtime contract and scope

Contact filter/pre-solve callbacks may use the listed snapshot identity/shape reads. Other stateful recursive calls return zero/default or no-op with EBUSY and a sticky operation name; zero alone is not success. Query visitors execute after unlocking and keep the existing nested-query behavior. C scene metadata and combined mappings have one exclusive scene-owner thread. Independent Rust registry access serializes across threads. A callback must not join a thread waiting to acquire the same registry. These checks do not establish unrestricted C API thread safety.

Sticky world/device failure remains separate from the thread-local API error. Check status/error immediately; clearing the API diagnostic or capacity diagnostics does not make a failed world usable. Worlds sharing a failed device remain terminal and destroyable. Rust callers must create a new device for recovery. The C adapter uses a process-wide shared device, so its supported recovery is a process restart; creating another C world does not heal that device.

The main runtime candidate passed 82 Rust selector processes containing 98 tests, plus 34 C fixtures across ordinary/native standalone/combined routes. Each route completed twelve lifecycle cycles with zero owned worlds/geometry after teardown, FD baseline/max 24/24 and thread baseline/max 6/6. The four cache-disabled lifecycle processes also pass. The supplemental phase exercises actual dispatch, replay-owned resource lifetime, growing/shrinking reset span, graph memo mutation and the full diagnostic recorder. Exact selectors, unchanged assertion counts, environments, timeouts, original failures and logs are in the phase protocols and receipts.

The final change after the main runtime matrices was only the replay diagnostic schema/typed flag count. Its emitted production key bytes are unchanged; the targeted native diagnostic rebuild/capture supplies change-specific evidence. Clean release builds then compile the final sources.

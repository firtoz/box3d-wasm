# UI08 — Replay load displays full Unix path instead of filename

- [x] Fixed and verified locally on all five routes; [repair and before/after evidence](UI08-repair.md).

`ReplayViewer::DrawLoadPopup` intends to show only the filename, but `strrchr(m_path, '\\')` recognizes only Windows separators. The actual Linux CPU load screenshot displays the entire absolute path; the auto-sized modal grows almost to the full1600px window instead of the intended26em. All four GPU load dialogs also display their full `/tmp/p10-*/a.b3rec` path. See [recording/replay acceptance](recording-replay-acceptance.json) and `raw/replay-gtk-path-runs/cpu/load-popup.png`.

Trace at the formatter boundary: input absolute `/home/firtoz/work/.../pr10-restart.b3rec`, last-backslash lookup null, displayed output=input rather than `pr10-restart.b3rec`. This is shared Replay UI code, not a recording/player engine defect. The project generator now uses the last Unix or Windows separator; player input is unchanged. Seven exact generated C++ cases and46 actual checks pass.

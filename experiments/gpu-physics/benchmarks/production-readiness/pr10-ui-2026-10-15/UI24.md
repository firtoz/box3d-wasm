# UI24 — Flat Height Field amplitude deletes the GPU floor

- [x] Fixed and verified locally; original diagnosis below is historical.

Mesh/Height Field exposes amplitude 0 as a valid value. The source deliberately switches to `b3CreateGrid` with scale `[2,0,2]`. Real CPU creates the flat heightfield. Ordinary/native standalone GPU returns a null shape, so actual world shape count becomes 0 and the floor disappears. Raising amplitude restores one shape. Both combined routes also lose the GPU floor while the mapped CPU floor remains valid. [Actual states and all-route before-repair images](geometry-controls-acceptance.json).

Original input/state evidence is in `raw/geometry-controls-runs/heightfield/<route>/receipt.json`: the amplitude-0 case has scale `[2,0,2]` on CPU, while standalone GPU retains a valid ground body but receives shape ID `[0,0,0]`, actual shape count 0 and no query hit. Original failed assertions remain unchanged.

Source chain: the sample's amplitude-0 branch constructs a flat grid; the C shim forwards its scale; `b3_create_height_field_shape` rejects any scale component `<= 0`. Zero Y scale is valid for the native flat grid. This is distinct from UI23's mesh safe-scale semantics: the repair must preserve flat heightfield geometry rather than inventing a nonzero amplitude.

The recovery-default radius assertion in this batch compares a nine-significant-digit serialized float with an exact JS float32 value. That separate harness predicate is invalid and will be adjudicated without rerunning the controls. It is not part of this defect.

Box3D/WASM and original scene defaults remain unchanged. Focused before/after repair images and applicable zero/positive heightfield cases are still required.
